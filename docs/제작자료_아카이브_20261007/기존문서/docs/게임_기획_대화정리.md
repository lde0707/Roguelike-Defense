# Rushitadel 게임 기획

기준일: 2026-10-05. 현재 기획과 제작 기준을 정리한다. 문서의 기능 명세와 Unity 구현 완료 여부는 별개이며, 구현 현황은 [구현 현황](구현_현황.md)을 따른다.

## 1. 게임의 중심

PC 탑뷰 전투에서 플레이어가 자전하는 기체를 움직이며 적과 보스의 공격을 피하고, 다섯 포탑의 성장 조합으로 런을 완성한다.

- 플레이어는 본체 1기와 본체에 부착된 포탑 5기로 구성한다.
- 포탑 ID는 T1~T5이며 회전·이동 후에도 동일하게 유지한다.
- 아군 생존 정보는 플레이어 현재 HP와 최대 HP로 단일 관리한다. 적·보스·적 투사체는 각자의 HP를 가진다.
- 피해·회복은 플레이어 HP에 적용하며 최대치를 넘지 않는다. HP 0이면 패배한다.
- 플레이어는 은색·보라색 기계 장갑과 보라색 중앙 코어로 표현한다.

## 2. 기획 상태

| 구분 | 내용 |
| --- | --- |
| 확정 구조·전투 | 5포탑 일체형 플레이어, 단일 플레이어 HP, 마우스 원거리 공격, 각 포탑 정면 비유도탄·사거리 약 3유닛, 절벽 벽과 적 탄 도탄·HP, 우클릭 범위 공격 |
| 런·성장 기준 | 3스테이지, 스테이지당 일반전 3회와 보스, 포탑 +12, +3/+6/+9/+12 증강, 정비 XP Web |
| 기능 제안 | WASD 이동, 자동 회전, 좌클릭 기본 사격, 고갈 후 60% 회복 잠금 해제, HP/동력 회복 선택 |
| 제작 검토 | 보스 채택·테마 총수·등장 순서, 피해·발사 간격·회복·충전·성장 비용·무적시간 |
| 실행 기준 | Unity 프로토타입의 수치는 테스트 기본값이며 최종 밸런스가 아니다. |

## 3. 런 진행

테마 2택1 → 일반전 1 → 정비 → 일반전 2 → 정비 → 일반전 3 → 정비 → 보스 → 다음 스테이지 또는 결과.

- 스테이지는 총 3개다. 동일 런에서 사용한 테마는 반복 선택하지 않는다.
- 일반전 종료 조건은 스폰 일정 완료와 생존 적 0을 함께 확인하는 안이다.
- 정비에서 플레이어 HP 또는 동력 회복을 선택하고 XP Web을 이용하는 안이다. 두 자원이 모두 최대치이면 회복 선택을 건너뛴다.
- 마지막 보스 격파 시 런 승리, 플레이어 HP 0이면 런 패배다.
- 동시 격파 시 패배 우선 여부, 보상과 저장 시점은 구현 전에 최종 확인한다.

## 4. 조작·전투

| 기능 | 동작 |
| --- | --- |
| 이동 | WASD, 중앙 전장 안에서 이동, 대각선 속도 정규화. 좌우 절벽은 보이지 않는 벽으로 통과 불가 |
| 자전 | 본체와 5개 소켓이 함께 회전, 슬롯 ID 고정 |
| 플레이어 원거리 공격 | 마우스 방향으로 조준해 발사. 좌클릭 유지 사격은 현재 조작 배치안이며 본체 자전과 독립 |
| 포탑 일반 사격 | 각 포탑의 정면으로 포탄 자동 발사. 적 탐색·타겟팅·유도 없이 발사 위치에서 약 3유닛 직진 |
| 우클릭 동력 공격 | 최대 기력 70% 소비, 짧고 약한 후방 반동, 본체 지름의 1.5배 원형 범위탄 |
| 우클릭 피해 | 중앙 반지름 30% 즉사. 바깥 영역은 대상 최대 HP의 100%에서 원 가장자리 50%까지 선형 감소 |
| 적 탄 | HP 보유. 아군 포탑·플레이어 공격으로 피해·파괴. 절벽 밖→안 통과, 안→밖 이탈 시에만 도탄 |
| 동력 회복 | 자동 충전, 0에 도달하면 동력 공격 잠금, 최대치 60%에서 해제하는 안 |
| 성장 선택 | T1~T5 슬롯을 선택해 강화·변형·증강 정보를 확인 |
| 시간 제어 | ESC 일시정지. 정비는 완전 정지, 전투 성장 UI는 10~20% 슬로모션 검토 |

동력 고갈 중에도 이동·자전·포탑 일반 사격은 동작한다. UI 입력과 전투 입력은 분리한다. 플레이어의 시각 배율과 피격 반경은 별도로 조정한다.

포탑은 적이 없어도 발사 주기에 따라 사격한다. 자전은 이후 발사할 방향을 바꾸며, 이미 발사된 포탄은 본체 이동·회전과 관계없이 발사 방향을 유지한다. 기본 포탄은 경로에서 처음 닿은 적 또는 적 탄에게 피해를 주고 소멸하며, 미충돌 시 누적 이동 거리 약 3유닛에서 소멸한다. 플레이어 기본 공격은 현재 동력을 소모하지 않는다. 플레이어 기본 공격의 사거리·피해·발사 간격은 별도 조정값이다.

적은 절벽 밖에서 플레이어 방향으로 투사체를 발사한다. 적 탄은 중앙 길로 진입할 때 반사되지 않고, 길 안에서 다시 절벽 밖으로 나가려 할 때 반사한다. 아군 탄은 벽을 통과해 바깥의 적을 공격할 수 있다. 적 탄 파괴로는 적 처치 XP를 지급하지 않는다.

우클릭은 지정 위치에 도착해 원 범위 안의 적·적 탄에 1회 피해를 준다. 대상 중심 거리 d/공격 반지름 R이 0.3 이하면 즉사, 그 외 원 안 피해는 최대 HP×(1−0.5×((d/R−0.3)/0.7))다. 원 밖에는 피해가 없다. 기력 부족 시 발사·소모·반동 모두 취소한다. 반동도 절벽 벽을 넘지 못한다. 반동 거리·시간, 적 탄 HP·탄속·수명은 테스트 조정값이다.

성장표의 추적 미사일·도탄 등은 별도 검토 후보이며 기본 포탑 발사 규칙에 적용하지 않는다. 채택할 경우 기본 직진탄과의 예외 규칙을 따로 확정한다.

### 전진 압박 전투 설계

카메라는 일정 속도로 월드 +Y 방향으로 전진한다. 플레이어는 월드 좌표에서 직접 움직이고 카메라에 붙이지 않는다. 따라서 입력 없이 서 있으면 화면상 뒤로 밀려나며, 전진 이동으로 카메라 속도를 이겨내야 한다. 정지한 지형·절벽 위 적이 화면 아래로 지나가도록 해 이동 요새가 아닌 플레이어 자신의 전진으로 읽히게 한다.

- 화면 하단: 테마별 후방 위험 구역. 카메라 기준 위치 고정, 접촉 중 1초마다 강한 환경 피해.
- 화면 상단: 카메라와 함께 전진하는 장벽. 본체 충돌 원이 통과하지 못하며, 아군·적 탄을 가로막지는 않는다.
- 좌우: 절벽 벽과 단방향 적 탄 도탄 유지. 벽은 카메라 주변 전장 전체를 계속 덮는다.
- 맵: 기존 1920×1080 연결 배경을 세로 반복 재배치한다. 적·탄·피해 범위는 월드 좌표를 유지해 카메라 이동으로 탄의 궤적이나 도탄 기준이 달라지지 않게 한다.
- 적 생성: 카메라 앞쪽의 좌우 절벽 밖에서 생성. 뒤로 지나간 적은 보상 없이 정리해 이후 생성이 막히지 않게 한다.
- 정지·패배: 카메라, 스크롤, 위험 구역 타이머, 연출을 함께 멈춘다. 새 게임은 진행 거리와 타이머를 초기화한다.

초기 테스트값: 카메라 0.8유닛/초, 플레이어 이동 2.5유닛/초, 후방 영역 화면 아래 1.2유닛, 접촉 1초마다 최대 HP의 50% 피해. 일반 피격 무적으로 환경 피해를 상쇄하지 않는다. 영역을 벗어나면 접촉 타이머가 초기화된다. 속도·피해·영역 깊이는 조정 가능하며 확정 밸런스는 아니다.

테마 표현: 풀=독안개/가시 장벽, 불=용암/화산암 장벽, 얼음=눈보라/빙벽, 물=해일/암초 장벽, 전기=전기폭풍/전기 장벽. 공통 충돌·피해 규칙에 테마별 색·형태·명칭을 적용한다. 첫 구현은 프로토타입 표현이며 최종 아트 리소스가 아니다.

## 5. 성장과 자원

- 골드: 포탑 강화에 사용.
- XP: 정비 중 Web 구매에 사용. 전투 중 획득분은 유지.
- 동력: 능동 공격에 사용.
- 포탑은 +12까지 강화하며 +3, +6, +9, +12에서 3택1 증강을 획득한다.
- +3은 변형 1개를 결정한다. +6/+9/+12는 공통·선택 변형 전용 증강 풀을 사용한다.
- 증강 단계에서는 일반 스탯 강화 대신 증강을 선택한다. 포탑별 최대 증강 수는 4개다.
- 비용·단계·효과 적용은 선택 확정 시 하나의 거래로 처리한다.
- XP Web은 관통·분산·폭발·독·동력·지원 6가지가 연결된 구조다. 선행 노드·비용·중첩 제한을 검증한다.
- XLSX의 개별 노드·효과 수치는 후보 데이터다. 미정 항목을 런타임 확정 값으로 자동 반영하지 않는다.
- 변형 ID S3-01~S3-15는 두 성장표에서 동일하게 사용한다. EX-01~EX-03은 채택 미정인 별도 검토 후보다.

## 6. 공통 아트·맵 기준

- 화면 상단에 보스, 하단에 플레이어를 배치한다. 적의 공격면은 카메라 정면이 아닌 화면 하단의 플레이어 방향이다.
- 기체 윗면이 읽히는 탑뷰 각도를 사용하며 전면을 과도하게 세우지 않는다.
- 면이 명확한 장갑, 절제된 외곽선과 매트 질감을 사용한다. 코어·공격부의 발광은 포인트로 제한한다.
- 좌우 절벽은 평행하게 배치하고 중앙 전장을 넓게 확보한다.
- 해저 중앙 바닥은 좌우 밝은 지형보다 낮게 읽혀야 한다. 절벽은 깊이가 보이되 전체 화면을 지나치게 어둡게 하지 않는다.
- 바닥 원형 무늬는 밀도를 낮춰 탄막과 혼동되지 않게 한다. 수중 물결빛·빛기둥은 사용하지 않는 방향이다.
- 배경·보스·플레이어의 채도와 명도를 분리한다. 아트 배율, 충돌 범위, 맵 이동 경계는 별도 데이터다.
- 이미지의 10%·20%·50% 조정 요청은 해당 시안의 상대 배율이며 전역 게임 단위로 해석하지 않는다.

## 7. 테마별 방향

| 테마 | 배경 | 보스 표현 |
| --- | --- | --- |
| 풀 평원 | 풀색 바닥, 돌·이끼 경계, 읽기 쉬운 절벽 | 매트 장갑에 잎맥, 지형과 구분되는 명도와 포인트 |
| 불·용암 | 따뜻한 화산색, 암석 경계 | 어두운 매트 장갑과 용암색 발광 |
| 얼음 | 밝은 얼음색 바닥·경계 | 차가운 장갑과 청색 코어, 고리 두께 절제 |
| 물·해저 | 청록·파랑의 낮은 해저 골짜기 | 심해 가오리 또는 수룡 등 검토 |
| 물·전기 | 밝은 하늘색 바닥 | 청색·황색 쌍 보스, 속성 구별 |

현재 5개 아트 방향을 사용한다. 전체 테마 수와 실제 보스 배정은 미정이다.

## 8. 보스별 제작 기준

### 거대 인간형과 독립 손

- 거대한 상체가 길을 막으며 몸통 하단은 지면에 박힌 느낌으로 표현한다.
- 손 2기는 독립적으로 부유하는 완성된 기계 유닛이다. 절단된 팔처럼 보이지 않게 한다.
- 손가락은 뽑기 기계처럼 3개가 같은 간격으로 배치된다.
- 레이저 발사 원점은 손바닥 중앙 코어다. 손가락 끝에서 발사하는 것처럼 보이면 안 된다.
- 하단 직선 레이저, 구체, 탄막은 패턴 후보다. Idle에는 공격 이펙트를 넣지 않는다.

### 얼음 고리

- 중앙 분할 장갑과 보석 코어, 좌우 고리 2기로 구성한다.
- 지면 파괴 없이 평탄한 바닥 위에 부유한다.
- 고리는 얇은 링으로 읽혀야 하며 두꺼운 원통이 되지 않게 한다.
- 공격면이 하단을 보는 상태와 좌우를 각각 보는 상태를 구별한다. 실제 채택 패턴은 미정이다.

### 풀 나비와 드론

- 나비는 큰 날개 2개와 작은 날개 2개의 기계형 실루엣을 유지한다.
- 날개·장갑에 절제된 잎맥과 식물성 질감을 더한다. 바닥과 같은 단색으로 묻히지 않게 색을 분리한다.
- 좌우에 소형 드론 4기가 배치된 시안을 기준으로 검토한다. 드론은 보스보다 훨씬 작게 표현한다.
- 각 드론은 날개 2개와 둥근 머리를 가지며 보스의 축소 복제품일 필요는 없다.
- 보스와 드론 모두 윗면이 보이고 하단 플레이어를 향한다.
- 드론의 소환 수·재생성·파괴 보상·공격 방식은 미정이다.

### 심해 가오리

기존 보스와 같은 게임 화면 각도·매트 기계 질감·상대 크기를 사용한다. 다양한 패턴을 담을 수 있도록 몸체와 공격 소켓을 설계하되 최종 패턴은 별도 확정한다.

### 네 머리 수룡

- 하나의 모체와 한 구덩이에서 네 목이 뻗어 나오는 구조다.
- 네 목의 뿌리는 한곳으로 읽혀야 하며 네 개의 독립 구덩이나 나뭇가지형 목 구조로 표현하지 않는다.
- 네 머리는 하단 플레이어를 향한다. 탑뷰에서도 공통 몸통과 목 연결이 읽혀야 한다.
- 순차 발사·교차 사선·합동 공격은 검토 후보다. 부위별 HP·파괴 규칙·동시 발사 수는 미정이다.

### 물·전기 쌍 보스

- 좌측 청색, 우측 황색 코어로 구별한다. 탑뷰 각도와 코어 위치를 일관되게 유지한다.
- 충전 시 상하 연결부와 보석이 짧게 전개되어 에너지를 모으는 느낌을 준다.
- 중앙에 바로 붙은 화살표형 장갑을 좌우로 약 20% 벌린 충전 시안을 사용한다.
- 바깥 부유 보석은 해당 장갑 전개와 별개이며 위치와 크기를 유지한다.
- 충전 상태에서는 레이저를 발사하지 않는다. 발사구·연계·격파 조건은 미정이다.

## 9. 보스 패턴·리소스 계약

공통 제안 상태: Idle → 방향 결정 → 준비·충전 → 발사 → 회복 → 다음 패턴.

패턴마다 ID, 발사 소켓, 전방 벡터, 조준 고정 시점, 예고 범위, 실제 피격 범위, 피해 간격, 활성 시간, 회복 시간을 기록한다. 사망 후 신규 공격을 중지하고 잔존 탄막 정책을 명시한다. 공격 예고와 판정은 일치해야 하며 회피 경로를 확보한다.

## 10. UI·저장 제안

- HUD: 플레이어 HP, 동력과 잠금 상태, 골드, XP, 스테이지·웨이브, T1~T5 성장 정보.
- 포탑 패널: 고정 슬롯 ID, 강화 단계, 변형, 증강, 비용·조건·적용 대상.
- 정비: 회복 선택 → XP Web → 출발.
- 저장: 3슬롯, 테마 확정·정비 완료·보스 보상 확정 등 안전한 경계에서 저장하는 안.
- 런 ID·시드·진행·사용 테마·플레이어 HP·자원·T1~T5 빌드·Web 노드·미완료 선택·보상 지급 여부를 저장한다.
- 손상 데이터는 검증 후 안내하고 보존한다. 저장 실패를 성공으로 표시하지 않는다.
- 메타 해금·승천·오버클럭 등은 후순위 검토다.

## 11. 문서 사용

UI와 시스템 PPT는 화면별 표·설명 양식을 유지한다. 상세 TXT는 규칙과 예외를, 성장 XLSX는 후보 ID와 효과를, drawio는 상태 흐름을 관리한다. 확정되지 않은 값은 '제안·미정·테스트값'으로 표시하고, 현재 구현 여부는 구현 현황 문서에서 확인한다.
