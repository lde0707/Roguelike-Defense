# 연결 배경

- 게임용: `연결배경_1920x1080.png` — 1920×1080, 불투명 PNG.
- 확인용: `연결배경_스크롤미리보기.gif` — 960×540, 아래 방향 반복 이동.
- 원본 `01_L.png`, `01_M.png`, `01_R.png`, `1920_1080배경.png`는 변경하지 않았다.

## 배치

화면 왼쪽부터 **R(윗땅) → 좌우 반전 M(절벽) → L(중앙 길) → M(절벽) → R(윗땅)** 순서다. 중앙 길이 낮고 양옆 땅이 높은 구조이며, 예시와 비슷한 길 폭과 타일 크기로 조립했다.

| 구역 | 가로 범위(px, 끝 제외) |
|---|---|
| 왼쪽 윗땅 | 0–288 |
| 왼쪽 절벽 타일 | 288–480 |
| 중앙 길 타일 | 480–1440 |
| 오른쪽 절벽 타일 | 1440–1632 |
| 오른쪽 윗땅 | 1632–1920 |

절벽 타일 자체에도 길·윗땅의 연결 여백이 포함되어 있다.

## 반복 스크롤

64×64 원본 타일의 세로를 최근접 샘플링으로 60칸에 맞춘 뒤 3배 확대하여, 각 반복 타일이 192×180px가 되도록 했다. 세로를 약 6.25% 압축한 것으로, 새 색상·블러 없이 원본 팔레트와 3×3 픽셀 격자를 유지한다. 180px 패턴 6개가 정확히 1080px를 채우므로 PNG의 끝과 시작을 이어서 반복할 수 있다.

- 같은 배경 두 장을 세로로 붙여 아래로 이동시킨다.
- 한 장이 화면 아래로 완전히 벗어나면 다른 장 바로 위로 옮긴다.
- 두 장의 간격은 **화면에 표시된 배경의 정확한 높이**로 유지한다.
- Unity에서 픽셀 선명도를 유지하려면 `Filter Mode: Point`, `Compression: None`, 밉맵 비활성화를 사용한다. UV로 스크롤하는 경우 `Wrap Mode: Repeat`를 사용한다.
- 원본 타일 기반이므로 작은 무늬의 규칙적 반복은 남는다.

## Unity 실행 연결

`Rushitadel2D/Assets/Image/ScrollingBattlefield.png`는 게임용 PNG의 동일 복사본이다. `inGame` 씬의 `Looping Battlefield`가 19.2×10.8유닛 패널 3개로 화면을 덮도록 재배치한다. 카메라가 월드 +Y로 전진하고 지형은 월드에 고정되므로 화면상 아래로 흐른다. 배경 자체에 하향 속도를 추가하지 않는다. 뒤쪽 위험 구역과 앞쪽 장벽은 카메라에 고정한다. 실제 동작·조절값은 `Rushitadel2D/README_2D.md`를 따른다.

재생성 스크립트: `tools/build-background.cjs` (Node.js + sharp). 저장소 루트에서 `node tools/build-background.cjs`로 실행한다. sharp가 별도 런타임에 있다면 해당 `node_modules` 경로를 `NODE_PATH`로 지정한다.
