# Rushitadel Unity 전투 프로토타입

Unity 6000.5.3f1 / URP 2D / Input System. 기준일: 2026-10-05.

`Assets/Scenes/Title.unity`에서 Play → 새 게임을 선택하거나 `Assets/Scenes/inGame.unity`를 직접 실행한다. 플레이어는 본체와 5개 포탑 T1~T5가 함께 움직이는 자전 유닛이다. 아군 생존 HP는 PlayerHealth 하나가 소유한다.

## 조작

- WASD: 본체 이동. 대각선 속도를 정규화한다. 좌우 절벽의 보이지 않는 벽이 본체 충돌 원 전체를 중앙 길 안에 제한한다.
- 마우스 방향 조준 + 좌클릭 유지: 플레이어 본체에서 원거리 기본탄을 발사한다. 조준은 본체 자전과 독립적이다.
- 자동: 본체와 5개 포탑이 회전하며, 각 포탑은 자기 정면으로 비유도 직진탄을 사격한다. 발사 위치에서 5유닛 비행 후 소멸한다.
- 우클릭: 최대 기력(동력)의 70%를 소비해 커서 위치로 원형 범위탄을 발사한다. 발사 반대 방향으로 짧고 약하게 반동한다. 목표 위치에 도착하면 1회 범위 피해를 준다.
- ESC: 일시정지. 재개·재시작·타이틀 이동을 제공한다.
- 플레이어 HP 0: 패배 화면. 재시작 또는 타이틀 이동만 가능하다.

## 전진 압박 전투

카메라는 플레이어와 독립적으로 +Y로 전진한다. 지형과 적은 월드에 남아 화면 아래로 지나가며, 입력 없이 정지하면 플레이어도 화면 뒤쪽으로 밀린다. W로 전진하며 도탄과 적을 상대해야 한다. 카메라에 플레이어를 붙여서 자동 전진시키는 방식이 아니다.

카메라 하단에는 테마 위험 구역, 상단에는 통과할 수 없는 전방 장벽을 고정한다. 장벽은 카메라와 함께 전진하므로 플레이어의 앞쪽 이동 공간도 계속 열린다. 앞 장벽은 플레이어 이동·반동만 제한하며 탄을 막거나 반사하지 않는다. 좌우 절벽의 적 탄 도탄 규칙은 그대로 유지한다.

후방 위험 구역에 본체 충돌 원이 닿으면 경고하고, 연속 접촉 1초마다 최대 HP의 50%를 차감한다. 영역을 벗어나면 접촉 타이머가 초기화된다. 일반 피격 무적으로 환경 피해를 막을 수 없다. 정지·패배 중 카메라와 피해 타이머도 멈춘다.

`Gameplay Systems → ForwardPressureController`에서 속도·영역 깊이·피해와 테마를 조절한다. 기본 테마는 Electric이다. Grass(독안개/가시), Fire(용암/화산암), Ice(눈보라/빙벽), Water(해일/암초), Electric(전기폭풍/전기 장벽)의 명칭·팔레트·프로토타입 형태를 제공한다. 최종 테마 선택 UI·테마별 맵·최종 VFX는 별도 제작 범위다.

## 테스트 기본값

포탑 사거리 5, 우클릭 비용 70%·지름 1.5배·중앙 30%·외곽 50%는 사용자 확정값이다. 나머지는 조절 가능한 테스트 기본값이다.

| 항목 | 값 |
| --- | --- |
| 플레이어 최대 HP / 피격 무적 | 100 / 0.5초 |
| 이동 / 자전 | 2.5 unit/s / 시계방향 30도/s |
| 절벽 안쪽 면 / 이동 중심 경계 | 벽 X ±5.4 / 본체 반지름 0.65 기준 중심 X ±4.75 / Y는 카메라 아래 끝~전방 장벽 |
| 카메라 / 시작 위치 | +Y 0.8유닛/초 / 플레이어 (0, -1) |
| 후방 위험 구역 | 화면 아래 1.2유닛 / 연속 접촉 1초마다 최대 HP의 50% |
| 전방 장벽 | 화면 위에서 0.35유닛 안쪽 / 두께 0.6유닛 / 본체 중심 상한은 장벽 아랫면−반지름 |
| 포탑 | 피해 25 / 발사 간격 0.5초 / 정면 사거리 5 / 탄속 10 |
| 플레이어 기본탄 | 피해 25 / 발사 간격 0.25초 / 사거리 8 / 탄속 10 |
| 동력 | 최대 100 / 충전 5/s / 고갈 후 60% 해제 |
| 동력 공격 | 최대 동력 70% / 본체 반지름×1.5(현재 0.975) / 투사체 속도 12 |
| 반동 | 발사 반대 방향 0.18유닛, 0.12초. 반동 중 이동 입력보다 반동 우선, 절벽 통과 불가 |
| 적 | HP 100 / 이동 1 / 접촉 거리 1.05 / 피해 10 / 간격 1초 |
| 원거리 적 / 적 탄 | 발사 간격 2초 / 탄 HP 25·피해 10·속도 4·반지름 0.12·수명 12초 |
| 테스트 스폰 | 2초마다 2기, 최대 동시 8기, X ±7.3 / Y=카메라 중심+1.5~5.5 / 화면 뒤 2유닛 통과 시 보상 없이 정리 |
| 경험치 | 적 1기당 20 / 게이지 100 / 수집 속도 14 |

동력 공격은 적과 적 탄 HP 모두에 적용된다. 대상 중심까지의 거리 d와 공격 반지름 R을 사용한다. d/R ≤ 0.3이면 즉사, 0.3 < d/R ≤ 1이면 피해 = 대상 최대 HP × (1 − 0.5 × ((d/R − 0.3) / 0.7)). 원 밖은 피해가 없다. 지름은 본체 CircleCollider2D의 실제 월드 지름 기준이며, 밝은 안쪽 원은 즉사 영역이다. 현재 HP 비례가 아니다.

밖에서 진입 중인 적 탄은 가까운 벽에 반사되지 않는다. 반대쪽 벽을 나가려 할 때 반사하며, 한 프레임에 진입과 여러 번 반사가 일어나도 경로를 나누어 판정한다. 플레이어·아군 탄은 적 탄과 구별하며, 아군 탄은 절벽 밖의 적을 공격할 수 있다. 적 탄이 플레이어에 맞으면 1회 피해 후 소멸한다. 무적 중 피격에도 탄은 소멸한다. 수명이 끝난 탄은 사라진다.

기력이 70% 미만이면 우클릭은 발사·소모·반동 모두 발생하지 않는다. 고갈 회복 잠금이 60%에 해제돼도 발사는 70% 이상에서 가능하다. XP 게이지의 100 단위 표시는 성장 선택 구현을 의미하지 않는다. 현재 스폰은 전투 테스트용 반복 생성이다.

포탑의 약 5유닛 사거리와 정면 비유도 발사는 확정된 전투 기준이다. 좌클릭 유지 사격은 현재 조작 배치안이며, 기본탄·포탑의 피해·탄속·발사 간격과 플레이어 기본탄 사거리 8은 테스트값이다. 포탄의 사거리는 발사 순간 위치에서 누적 비행 거리로 계산하므로 발사 후 본체 이동으로 연장되지 않는다. 아군·적 투사체 모두 CircleCast로 이동 경로를 검사한다.

## 기획 단계 기능

3스테이지·웨이브·정비·승리 흐름, 골드와 +12 강화, 변형·증강, XP Web 구매, 최종 보스·패턴, 3슬롯 체크포인트 저장은 명세 단계다. [구현 현황](../docs/구현_현황.md)에서 범위를 확인한다.

현재 플레이어·적·탄환·테마 위험 구역은 기능 검증용 도형이다. 실행 배경 `Assets/Image/ScrollingBattlefield.png`는 `IMG/배경/연결배경_1920x1080.png`의 동일 복사본이며, 19.2×10.8유닛으로 표시한다. Point 필터·무압축·밉맵 비활성으로 연결 타일의 색과 픽셀을 유지한다. `LoopingBattlefield`는 화면을 덮는 3개 패널을 재배치한다. 카메라가 전진하므로 배경에 별도의 하향 이동을 중복 적용하지 않는다. 기존 원본 이미지와 PSD는 보존한다.

## 코드 구성

- Player: 이동, 단일 HP, 회전 리그, 마우스 기본 공격, 동력 공격.
- Combat: 포탑, 근접·원거리 적, 레지스트리, 비유도 직진탄, HP가 있는 적 탄, 단방향 도탄 경계와 공통 피해 계약.
- Power: 정상/회복 상태와 자원 검증.
- Progression: XP 누적과 수집.
- Spawning: 테스트 스폰.
- World: 카메라 전진·앞뒤 압박, 반복 배경, 테마 표현, 뒤로 지나간 적 정리.
- Presentation: 타이틀, HUD, 일시정지·패배.
- Editor: 명시적 씬 생성과 플레이 모드 검증.

`Rushitadel 2D → Rebuild Gameplay Scene`은 생성 씬과 프리팹을 테스트 기본값으로 재생성한다. 직접 수정한 씬은 먼저 별도로 보존한다. 에디터 재로드만으로 자동 재생성되지 않는다.

## 검증 재실행

다른 Unity 에디터에서 프로젝트를 닫은 상태에서 실행한다.

```powershell
& 'C:/Program Files/Unity/Hub/Editor/6000.5.3f1/Editor/Unity.exe' -batchmode -projectPath '<Rushitadel2D 절대 경로>' -executeMethod Rushitadel.Editor.PortValidation.Run -logFile '<로그 절대 경로>'
```

씬 재생성과 검증을 함께 하려면 `PortValidation.BuildAndRun`을 사용한다. `-quit`은 붙이지 않는다. 테스트가 Play Mode에서 실행된 뒤 직접 종료한다. 성공 표시는 `RUSHITADEL_2D_VALIDATION_SUCCESS`다. 검증 코드의 입력 장치 생성은 에디터 전용이며 게임 빌드에 포함되지 않는다.

결과와 검증 경계: [Validation](Documentation/Validation.md).
