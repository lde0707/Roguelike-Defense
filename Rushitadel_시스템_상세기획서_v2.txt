01. 게임 개요 · 플레이어와 핵심 시스템
========================================================================
상태: 플레이어 1기·부착 포탑 5기 / 플레이어 HP 단일 관리

구분 | 기준
게임 방향 | PC 탑뷰 / 자전하는 5포탑 플레이어 / / 런 성장과 보스 패턴 대응
플레이어 | 원형 기체 1기 + 부착 포탑 T1~T5 / 보라 코어
생존 정보 | 플레이어 HP 하나로 피해·회복·생존 관리
성장 구조 | 3스테이지·3일반전 / 강화 +12 / 증강 / XP Web
기능 제안 | 동력 충전 / 회복 선택

[1] 플레이어 구조
플레이어 한 기에 포탑 5기가 부착된다.
T1~T5는 회전 중에도 동일한 ID를 유지한다.
피해와 회복은 플레이어 HP에 적용한다.

[2] 기획 상태
확정: 플레이어 구조·단일 HP·시각 기준, 마우스 원거리 공격, 포탑 정면 비유도탄·사거리 약 5유닛.
확정: 절벽 이동 차단, 밖→안 진입 후 안→밖 이탈 시에만 적 탄 도탄, 적 탄 HP와 파괴.
확정: 우클릭 최대 기력 70% 소모·짧은 후방 반동·본체 지름 1.5배 원, 중앙 반지름 30% 즉사·외곽 최대 HP 100%→50% 피해.
제안: WASD·좌클릭 조작 배치, 동력 충전·회복 동작.
미정: 피해·발사 간격 등 세부 수치와 밸런스.

[3] 시스템 범위
런 진행·전투·성장·보스·저장·UI 연동.
각 기능의 상태 전이와 예외 처리를 정의한다.

[4] 플레이 경험
자전하는 5포탑 플레이어를 움직여 공격을 피한다.
포탑 증강과 Web 성장으로 매 런 빌드를 만들고
테마별 보스 패턴에 대응한다.

02. 런 진행 · 3스테이지 기본 구조
========================================================================
상태: 3스테이지 / 스테이지당 3일반전과 보스전

테마 2택1 → 일반전 1 → 정비 → 일반전 2 → 정비 → 일반전 3 → 정비 → 보스 → 다음 / 결과

[1] 시작
새 런 생성 → 테마 두 후보 생성 → 하나 확정.
스테이지마다 사용한 테마를 중복 선택하지 않는다.

[2] 일반전 종료
스폰 일정 완료 + 생존 적 0을 종료 조건으로 제안.
종료 보상은 한 번만 지급하고 정비로 이동한다.

[3] 정비
회복 선택 → XP Web → 출발.
일반전 3회마다 각각 정비를 거친다.
3회차 정비 이후 보스전에 진입한다.

[4] 보스 이후
격파 → 보상 확정 → 다음 스테이지 테마 선택.
3번째 스테이지 보스 격파 시 런 승리.
패배 조건은 SYS-06 참조.

03. 테마 · 맵 구조와 속성별 아트 기준
========================================================================
상태: 테마 시각 기준 / 등장 순서·전체 테마 수 미정

테마 | 지형 / 보스 방향
풀 평원 | 풀색 바닥·바위 경계 / 잎맥 나비 + 소형 드론
불·용암 | 따뜻한 화산색 / 매트 장갑과 용암 발광
얼음 | 밝은 얼음색 / 얇게 읽히는 좌우 2개 고리
물·해저 | 청록·파랑, 해저 골짜기 / 가오리·수룡 후보
물·전기 | 밝은 하늘색 바닥 / 청색·황색 쌍 보스 후보

[1] 공통 구도
평행한 좌우 절벽과 넓은 중앙 전투 공간.
물 테마 중앙은 양옆보다 낮게 표현한다.
절벽 음영은 깊이만 전달하고 너무 어둡지 않게 한다.

[2] 가독성
바닥의 동그라미 무늬를 줄이고 물결빛은 제외.
보스·탄막과 배경의 색·명도를 구분한다.

[3] 데이터 경계
ThemeData는 팔레트·배경·적 풀·보스 후보를 연결.
같은 아트 변형이 별도 테마인지는 승인 후 결정.

[4] 테마 구성
현재 5개 아트 방향을 바탕으로 테마 풀을 검토.
전체 테마 수와 등장 조합은 별도 확정한다.
맵 폭·스프라이트 배율·충돌 크기는 구분한다.

04. 플레이어 · 이동 / 자전 / 원거리 공격
========================================================================
상태: 마우스 원거리 공격 / 포탑 정면 비유도 직진탄·사거리 약 5유닛

항목 | 전투 기준과 조작 배치안
이동 | W·A·S·D로 본체를 조작 / 중앙 전장 내부 이동
자전 | 본체가 지속 자전 / 포탑 소켓도 함께 회전 / 회전 속도와 방향은 데이터로 관리
플레이어 사격 | 마우스 방향 원거리 공격 / 좌클릭 유지 발사는 조작 배치안 / 자전과 독립 조준
포탑 사격 | 각 포탑 정면으로 비유도 직진탄 자동 발사 / 적 유무와 무관 / 발사 위치에서 약 5유닛 비행
동력 공격 | 커서 위치 지정 + 우클릭 / 최대 기력 70% 소모 / 비용 부족·고갈 상태에서는 발사·반동 불가
상호작용 | 슬롯 클릭으로 T1~T5 선택 / 선택 포탑의 강화·변형·증강 정보 확인

[1] 확정된 외형
은색·보라색 아군 기계, 본체와 5포탑이 연결된 형태.
화면 하단에서 상단 보스와 대치한다.

[2] 포탑 발사 규칙
본체 자전으로 각 포탑의 소켓 위치와 정면이 함께 변한다.
포탑은 적을 탐색하거나 추적하지 않고 발사 간격마다 정면으로 사격한다.
포탄은 발사 순간 방향을 유지하며 본체의 이후 이동·회전에 영향을 받지 않는다.
처음 충돌한 적 또는 적 탄에게 피해를 주고 소멸한다. 미충돌 시 누적 비행 거리 약 5유닛에서 소멸한다.
플레이어 마우스 기본 공격은 별도 입력이며 현재 동력을 소모하지 않는다.
추적 미사일·도탄 변형은 검토 후보이며 채택 시 예외 규칙을 별도 확정한다.

[3] 입력 분리
UI 클릭은 전투 입력으로 전달하지 않는다.
일시정지·정비에서는 이동·사격·회전을 정지.
키 재지정은 UI 가이드와 함께 갱신한다.

[4] 크기·확정 값
시안의 플레이어 50% 축소는 아트 배율.
포탑 사거리는 약 5유닛. 충돌 반경·이동속도·회전속도·피해·발사 간격은 조정한다.
방향·피격·발사 소켓을 같은 좌표 기준으로 관리.

[5] 절벽 벽과 적 투사체
보이지 않는 좌우 절벽 벽으로 플레이어의 이동과 반동을 차단한다.
적은 벽 밖에서 중앙 길의 플레이어 방향으로 투사체를 발사한다.
밖→안 진입은 통과, 안→밖 이탈 시에만 벽 법선 기준 반사한다. 아군 탄은 절벽을 통과한다.
적 탄은 HP를 가지며 포탑·기본 공격·우클릭 범위 공격으로 파괴할 수 있다.
적 탄 파괴 시 적 처치 XP를 주지 않는다. 플레이어 피격·HP 0·수명 종료 시 탄이 소멸한다.
고속 이동 중에도 경로를 검사하며 한 프레임의 진입·다중 도탄을 처리한다.

[6] 우클릭 원형 범위탄
지름은 플레이어 본체의 1.5배. 커서 위치에 도착하면 대상별 1회 피해.
중앙 반지름 30% 안의 적은 즉사. 원 밖은 피해 없음.
나머지 영역은 피해 = 대상 최대 HP × (1 − 0.5 × ((d/R − 0.3) / 0.7)).
d는 공격 중심에서 대상 중심까지 거리, R은 공격 반지름. 가장자리는 최대 HP의 50% 피해.
적 투사체 HP에도 같은 비례 피해 적용. 현재 HP 비례가 아니다.
발사 직후 짧고 약하게 발사 반대 방향으로 반동. 벽 바깥으로 밀리지 않는다.

[7] 전진 압박과 카메라
카메라는 월드 +Y로 일정하게 전진하며, 플레이어는 월드 좌표에서 독립적으로 움직인다.
반복 타일 지형과 절벽 위 적은 화면 아래로 지나간다. 플레이어가 멈추면 화면 뒤로 밀린다.
화면 하단에는 추격 위험 구역, 상단에는 통과 불가능한 장벽을 카메라 기준 위치에 고정한다.
상단 장벽은 플레이어 이동·반동만 막으며, 좌우 절벽의 적 탄 단방향 도탄은 유지한다.
후방 구역에 연속 접촉하면 1초마다 강한 환경 피해. 구역 이탈 시 접촉 타이머 초기화.
일반 피격 무적은 환경 피해를 차단하지 않는다. 정지·패배 시 진행·피해 타이머도 정지한다.
테스트값: 카메라 전진 0.8유닛/초, 후방 깊이 1.2유닛, 초당 최대 HP 50% 피해.
테마 표현: 풀 독안개·가시 / 불 용암·화산암 / 얼음 눈보라·빙벽 / 물 해일·암초 / 전기폭풍·전기 장벽.
테마 표현은 교체 가능한 프로토타입이며 최종 리소스는 별도 제작한다.
적은 카메라 전방 좌우 절벽 밖에 생성. 화면 뒤로 지나간 적은 보상 없이 정리한다.
반복 배경은 1920×1080 연결 이미지를 세로 재배치하며 카메라 전진과 별도 하향 속도를 중복 적용하지 않는다.

05. 피해와 생존 · 플레이어 HP
========================================================================
상태: 생존 정보: 플레이어 HP / 피해 세부 수치 미정

항목 | 처리 기준
HP 관리 | 플레이어 현재 HP / 최대 HP 단일 관리
피해 적용 | 유효한 피격 이벤트마다 플레이어 HP 차감
회복 적용 | 플레이어 HP 증가 / 최대 HP까지 제한
적 목표 | 적의 공격 대상은 플레이어 / 조준 규칙은 데이터화
패배 조건 | 플레이어 HP 0이면 사망 처리 후 런 결과로 이동

[1] 생존 판정
플레이어 HP를 생존 판정에 사용한다.
HP 0에서 사망 상태로 전환한다.
사망 진입 이후 이동·사격·성장 입력을 차단한다.

[2] 피해 판정 제안
피격 영역에서 유효한 타격을 판정한다.
같은 공격 이벤트를 중복 적용하지 않는다.
지속·다단 공격의 피해 주기는 패턴 데이터로 관리.

[3] 동시 격파 제안
같은 틱에 플레이어와 보스가 죽으면 패배 우선안.
결과·보상 처리는 종료 관리자가 한 번만 실행한다.

[4] 튜닝 대상
최대 HP / 피해량 / 무적시간 / 보호 규칙.
피격 영역과 기체의 시각 크기를 구분한다.
피해 원인과 적·패턴 ID를 기록한다.

06. 동력 · 공격 비용 / 고갈 / 회복
========================================================================
상태: 우클릭 최대 기력 70% 소모 확정 / 충전·고갈 해제 기준은 제안 / 이동·일반 사격 유지

동력 정상 → 스킬 비용 소모 → 동력 0 → 공격 잠금·충전 → 60% 회복 → 정상 복귀

[1] 소모
우클릭 범위 공격 시 최대 동력의 70%를 지불한다.
현재 동력이 비용보다 적으면 사용을 제한한다.
처치 환급은 공격 비용보다 적게 제한하는 안.

[2] 충전 제안
동력은 전투 중 자동 회복.
고갈 시 동력 공격만 잠그고 이동·자전·포탑 사격 유지.
충전율은 미정. 우클릭 비용은 최대치의 70%로 확정.

[3] 재가동 제안
고갈 후 최대치의 60% 도달 시 잠금 해제안.
잠금 해제 후에도 70% 이상을 보유해야 우클릭을 발사할 수 있다.
일반전·보스전에 동일한 자원 상태 규칙 적용.
잠금·해제 상태를 HUD와 동기화한다.

[4] 검수
정비·일시정지에서는 시간 기반 회복도 정지.
스킬 입력 중복 차감·음수 동력·상한 초과 방지.
60% 기준은 테스트 후 확정한다.

07. 포탑 강화 · +12와 4개 증강 구간
========================================================================
상태: 최대 +12 강화 / 포탑별 증강 4개

+1 → +2 → +3 변형 선택 → +4 → +5 → +6 증강 → +7 → +8 → +9 증강 → +10 → +11 → +12 증강

[1] 일반 강화
골드 사용, 현재 단계 +1.
일반 단계는 해당 포탑의 강화 데이터 적용.
MAX +12 이후 강화 불가.

[2] 증강 단계
+3 / +6 / +9 / +12에서 3택1 증강.
해당 단계는 일반 스탯 강화 대신 증강 선택으로 처리.

[3] 변형·증강
+3은 변형 결정, 이후 공용·변형 전용 풀 사용.
포탑당 4개 증강.
변형별 효과와 수치는 증강 데이터에서 관리한다.

[4] 트랜잭션
조건 검증 → 선택 완료 → 비용 차감·단계·효과 적용.
취소·저장 복원으로 무료 강화가 생기지 않게 한다.
UI-07·08과 같은 데이터 원본을 사용한다.

08. 플레이어 HP 회복 · 정비 처리
========================================================================
상태: 플레이어 HP 회복 처리 / 회복량 미정

정비 진입 → 회복 항목 선택 → 회복량 검증 → 플레이어 HP 반영 → Web 성장

[1] 회복 시점 제안
일반 웨이브 종료 후 정비에서 회복 보상 선택.
플레이어 HP와 동력의 현재·최대 값을 확인한다.
회복할 여지가 있는 항목을 선택할 수 있다.

[2] 회복량 계산
HP 회복 선택 시 지정된 회복량을 적용한다.
회복 후 HP = 현재 HP + 회복량, 최대 HP까지 제한.
정액·비율 방식과 수치는 미정이다.

[3] 적용 처리
보상 ID를 기준으로 회복을 한 번만 적용한다.
실제 회복량과 갱신된 HP를 UI에 전달한다.
이미 처리한 보상은 다시 적용하지 않는다.

[4] 단계 완료
회복 적용 또는 건너뛰기 후 XP Web으로 이동.
정비 완료 데이터에 플레이어 HP를 저장한다.
전투 중 회복 효과는 채택 시 별도 데이터로 정의.

09. XP Web · 연결형 런 성장
========================================================================
상태: XP Web 구조 / 구매 처리 규칙

연결 가지: 관통 / 분산 / 폭발 / 독 / 동력 / 지원

[1] 구매 시점
XP를 축적하고 정비 중에만 노드를 구매한다.

[2] 연결 구조

효과 / 등급 / 비용 / 연결 ID / 중첩 규칙.

[4] 런 경계
구매 확정 시 한 번만 XP 차감·효과 적용.
저장에는 노드 ID를 기록하고 로드 시 검증.
영구 성장과 혼합하지 않는다.

웨이브 이벤트·미니 엘리트·오버클럭은 후순위.

18. 포탑 변형 ID와 성장표 적용
========================================================================
S3-01 삼연장 버스트 / S3-02 머신건 포탑 / S3-03 확산 산탄포
S3-04 스나이퍼 포탑 / S3-05 레일 포대 / S3-06 거대 대포
S3-07 유탄 발사기 / S3-08 도탄포 / S3-09 화염 분사포
S3-10 산성 분사포 / S3-11 냉각 방사포 / S3-12 파쇄 표식포
S3-13 전격 코일포 / S3-14 충격파 포탑 / S3-15 추적 미사일포

위 15종은 기본 변형 후보 풀이다. 실제 해금 순서·등장 가중치는 미정이다.
EX-01 중량 산탄포 / EX-02 분열 포탄포 / EX-03 집속 미사일포는 추가 검토 후보이며 기본 풀 밖에서 관리한다.
일반 강화는 S2 계열, 공통 증강은 UC 계열, 변형 전용 증강은 VariantID + LocalID로 식별한다.
XLSX의 '2단계_스탯', '3단계_변형'은 편집 분류명이며 스테이지 번호가 아니다.
레어/에픽/유니크 표기는 희귀/영웅/고유 등급과 각각 대응한다.

성장표의 수치와 횟수는 밸런스 후보다. '미정' 값을 0으로 변환해 적용하지 않는다.
일반 강화 효과의 대상은 선택한 SlotID, Web 공통 효과의 대상은 플레이어 빌드다.
플레이어 전체 버프는 슬롯별 중복 부착으로 5배 적용되지 않도록 효과 소유자를 명시한다.
+3/+6/+9/+12는 증강 선택 단계이며 일반 스탯 효과를 함께 지급하지 않는다.
취소·연속 클릭·불러오기에도 비용·단계·효과는 정확히 한 번 처리되어야 한다.
후보 생성 시 보유 증강, 변형 조건, 최대 중첩, 상호 배타, 무효 대상을 제외한다.
후보가 3개 미만일 때의 보충·재추첨 정책은 채택 전에 확정한다.

19. 적·상태이상·피해 데이터 제안
========================================================================
적 역할: 일반 진입 / 돌진 / 탱커 / 원거리 / 엘리트.
적이 위협하고 공격하는 대상은 플레이어 본체다.
타겟 우선순위, 이동 경로, 접촉 반경, 공격 예고, 피해 간격은 EnemyData에서 관리한다.
맵 밖·피격 불가·사망 대상을 공격 후보로 선택하지 않는다.

상태 후보:
- 화상: 일정 시간 지속 피해.
- 독: 제한된 중첩을 누적하는 지속 피해.
- 부식: 방어력 약화. 중첩과 하한 검증.
- 둔화·빙결: 이동·행동 제어. 보스 저항을 별도로 정의.
- 감전: 연쇄 타격 또는 제한된 경직.
- 표식: 후속 포탑 피해 증폭. 중복 정책 명시.

DamageEvent 제안 필드:
AttackID / SourceID / OwnerSlotID / TargetID / BaseDamage / Tags / HitTime.
지속 피해와 파생 투사체는 원본 소유자와 재발동 허용 여부를 기록한다.
동일 이벤트 중복 적중 방지와 별개로 다단 공격은 명시된 간격마다 새 이벤트를 발생시킨다.
치명타·방어·증폭·지속 피해의 계산 순서와 수치는 밸런스 확정 전 테스트 대상으로 둔다.
적·보스의 상태 면역과 플레이어의 피격 무적은 서로 다른 데이터다.

20. 데이터·저장 계약 제안
========================================================================
PlayerRuntime: CurrentHP / MaxHP / Position / Rotation / Gold / XP / PowerState.
TurretRuntime[5]: SlotID / UpgradeLevel(0~12) / VariantID / AugmentIDs(최대 4).
WebRuntime: PurchasedNodeIDs / SpentXP / AppliedEffectKeys.
RunRuntime: RunID / Seed / StageIndex / WaveIndex / State / UsedThemeIDs.
RewardRuntime: RewardID / OfferedChoices / SelectedChoice / Applied.
BossRuntime: BossID / PatternID / Phase / AimDirection / TelegraphState / HP.
SaveEnvelope: SchemaVersion / SavedAt / SlotID / Payload / IntegrityData.

현재 HP는 0~최대 HP 범위다. 포탑 슬롯 배열은 중복 없는 T1~T5로 검증한다.
강화 단계와 증강 개수, 변형 전용 증강의 소속이 일치해야 한다.
효과는 데이터 ID로 재구성하며 저장된 배율을 다시 곱해 중복 적용하지 않는다.
슬롯 덮어쓰기 확인, 임시 파일 검증·원자 교체, 직전 정상 저장본 보존을 제안한다.
기록되지 않은 ID나 손상 파일은 정상 슬롯으로 처리하지 않는다.
체크포인트에서 미완료 선택과 지급 여부를 유지해 재추첨·중복 보상을 방지한다.
임의 전투 시점 저장은 체크포인트 저장과 별도의 기능이다.

21. 입력·시간·화면 상태 제안
========================================================================
우선순위: 결과 > 일시정지 > 정비 > 성장 선택 > 전투.
결과 상태에서는 이동·회전·공격·구매·시간 복귀 입력을 차단한다.
일시정지는 0배속이며 닫을 때 직전 상태의 시간 배율로 돌아간다.
정비도 0배속이고 XP Web 구매와 회복 선택만 허용한다.
전투 중 성장 선택 UI는 10~20% 슬로모션을 검토하되 실제 배율은 미정이다.
UI 위에서 입력한 클릭은 동력 공격이나 다른 전투 동작에 전달하지 않는다.
월드 발사각과 화면 UI 슬롯 순서를 분리하고 회전 중에도 선택 SlotID를 유지한다.
피격·보스 사망·웨이브 종료가 겹치면 런 종료 관리자가 결과와 보상을 1회 결정한다.

동력 회복, XP 수집, 일시정지·패배·재시작.
