1. 게임 기본 정의
======================================================================

1-1. 장르
[확정]
- PC 전용 캐주얼 로그라이크 타워디펜스.
- 자동 포탑 방어와 플레이어 직접 조작 전투를 결합한다.
- 한 번의 런 안에서 플레이어와 포탑이 각각 다른 방식으로 성장한다.

1-2. 핵심 콘셉트
[확정]
- 이동하는 요새가 아래에서 위 방향으로 전진한다.
- 플레이어는 요새 내부를 직접 이동하며 전투한다.
- 기지 좌측 3개, 우측 3개, 총 6개의 자동 포탑이 존재한다.
- 적은 기지의 좌우 측면에서 출현해 요새를 추격한다.
- 플레이어는 기본 공격, 동력 공격, 포탑 업그레이드, 포탑 재건,
  동력 관리, 보스 패턴 대응을 직접 수행한다.
- 포탑은 기본 방어선을 담당하고 플레이어는 전투 상황에 능동적으로 개입한다.

1-3. 핵심 플레이 판단
[확정 + 개정]
플레이어는 전투 중 다음 행동 중 무엇을 우선할지 계속 판단한다.
1) 기본 공격으로 적을 직접 제거할지
2) 동력 공격으로 몰려 있는 적을 빠르게 정리할지
3) 동력을 아껴 비상 상태를 피할지
4) 골드를 사용해 포탑을 강화할지
5) 파괴된 포탑을 재건할지
6) 특정 측면의 방어가 무너지기 전에 이동할지
7) 보스 패턴 파훼를 위해 동력을 남길지
8) [신규] 다음 웨이브 예고를 보고 어느 측면을 미리 강화할지

2. 한 게임의 전체 진행 구조
======================================================================

2-1. 런 구성
[확정]
- 한 게임은 총 3개의 스테이지로 구성된다.
- 각 스테이지에는 일반 웨이브 3개가 존재한다.
- 각 일반 웨이브가 끝날 때마다 정비 라운드가 존재한다.
- 3번째 웨이브가 끝난 뒤에도 정비를 진행한 후 보스전에 진입한다.
- 각 스테이지 마지막에는 해당 테마의 보스가 등장한다.
- 스테이지 3 보스를 처치하면 해당 런을 최종 클리어한다.

2-2. 전체 진행 순서
[확정] (v1.0 동일)
게임 시작 → 테마 2택1
→ 스테이지 1: 웨이브1 → 정비 → 웨이브2 → 정비 → 웨이브3 → 정비 → 보스
→ 테마 2택1
→ 스테이지 2: (동일 구조)
→ 테마 2택1
→ 스테이지 3: (동일 구조)
→ 게임 클리어

2-3. 한 런의 기본 콘텐츠 수
- 스테이지 3개 / 일반 웨이브 9개 / 보스전 3회 / 테마 선택 3회
- 한 런에서 경험하는 테마: 3종 / 전체 테마 후보: 8종

4. 웨이브 시스템
======================================================================

4-1. 기본 구조
[확정]
- 각 스테이지에 일반 웨이브 3개.
- 적은 시간 기반 고정 출현값(타임라인 데이터)으로 등장한다.

4-2. 웨이브 데이터 예시
[예시] (v1.0 동일)
0초: 일반 적 4 / 15초: 일반 적 6 / 30초: 돌격형 2 + 일반 적 5
50초: 원거리형 3 / 70초: 탱커 2 + 일반 적 8 / 90초: 엘리트 1

4-3. 고정 출현 방식의 이유
[확정] (v1.0 동일: 난이도 곡선 통제, QA 재현성, 비상 웨이브 삽입 용이)

4-4. 일반 웨이브 상태
[확정] (v1.0 동일)

4-5. 웨이브 종료 조건
[신규 / 제안]
- 웨이브 종료 = 타임라인 스폰 완료 + 필드 잔존 적 전멸.
- 마지막 스폰 후 일정 시간(예: 60초) 이상 잔존 적이 남아 있으면
  잔존 적에게 점감 디버프(받는 피해 증가)를 걸어 소모전 늘어짐을 방지한다.
- 잔존 적 강제 소멸은 사용하지 않는다. (처치 보상 손실 방지)

4-6. 웨이브 예고 시스템
[신규 / 제안]
- 정비 라운드와 웨이브 시작 직전, 다음 웨이브의 요약 정보를 표시한다.
  1) 좌/우 압박 비율 (예: 좌측 집중 / 균등 / 우측 집중)
  2) 주요 적 타입 아이콘 1~3개 (예: 탱커 다수, 원거리 포함)
  3) 엘리트 등장 여부
- 목적: "어느 측면을 미리 강화할까"라는 사전 전략 판단을 만든다.
- 테마 선택 = 스테이지 예고, 웨이브 예고 = 웨이브 단위 예고로
  예고 구조를 2단계로 통일한다.
- 정확한 수치가 아니라 방향 정보만 준다. (완전 정보화 방지)

4-7. 웨이브 이벤트 슬롯
[신규 / 제안]
- 고정 타임라인 위에 웨이브당 0~2개의 이벤트 슬롯을 둔다.
- 슬롯에서 발생 가능한 이벤트(런마다 무작위):
  1) 보급 드랍: 필드에 골드/경험치 보급이 떨어짐. 주우러 가는 리스크/리턴
  2) 미니 엘리트 난입: 예고 없는 소형 엘리트 1기
  3) 테마 이벤트: 테마별 고유 환경 효과 (예: 시야 감소, 지형 장애물)
- 이벤트 슬롯의 발생 시점은 고정, 내용만 무작위로 하여 QA 재현성을 유지한다.
- 목적: 2~3회차 이후 웨이브 암기로 인한 긴장감 소실 방지.

5. 정비 라운드
======================================================================

5-1. 등장 시점
[확정] (v1.0 동일)
- 모든 일반 웨이브 종료 후. 웨이브 3 종료 후에도 정비를 거쳐 보스전 진입.

5-2. 주요 기능
[개정] UI 방향성 문서 6-4(회복 선택)와 정합화. 회복 3택을 정식 편입.
정비 라운드는 두 단계로 구성된다.

A. 회복 선택 (선 진행)
- 3개 내외 선택지 중 1개 선택:
  1) 플레이어 체력 회복
  2) 기지 체력 회복
  3) 동력 회복
- [제안] 회복량은 고정 % (예: 각 40~60% 구간에서 테스트).
- [제안] 셋 다 온전할 때는 대체 보너스 선택지(소량 골드/경험치)를 노출한다.

B. 플레이어 Web 업그레이드
- 경험치 사용, 현재 빌드 확인, 다음 웨이브/보스 준비.

C. 정보 표시
- 다음 웨이브 예고(4-6)를 정비 화면에 함께 표시한다.

5-3. 포탑 강화와의 차이
[확정] (v1.0 동일)
- Web: 정비 라운드 전용 / 포탑: 전투 중에도 가능.

5-4. 설계 목적
[확정 + 개정]
- 성장 선택을 전투 중 조작과 분리한다.
- [신규] 회복 3택으로 정비 라운드에 "선택의 무게"를 부여해
  단순 스킬트리 화면이 아닌 기대되는 쉼표로 만든다.

7. 플레이어 시스템
======================================================================

7-1. 조작
[확정] (v1.0 동일)
- 직접 이동, 마우스 조준, 자동 타겟팅 아님.

7-2. 기본 공격
[확정] (v1.0 동일)
- 마우스 방향 투사체. 동력 비소비. 자동 추적 없음.

7-3. 플레이어 기본 스탯
[확정] (v1.0 동일)
- 공격력 / 체력 / 공격속도 / 이동속도 / 방어구 관통력 / 치명타 확률 / 치명타 피해량

7-4. 수동 투사체 방식의 설계 영향
[확정] (v1.0 동일)

7-5. 플레이어 다운 / 사망 규칙
[신규 / 제안]
v1.0에 플레이어 HP 0 처리 규칙이 없어 신설한다.
즉시 게임오버는 캐주얼 타겟에 과하므로 "다운-복귀" 구조를 제안한다.

A. 다운 발생
- 플레이어 HP 0 → 다운 상태.
- 다운 즉시 기지 코어 위치로 귀환(연출: 비상 회수).

B. 다운 페널티
1) 복귀 대기 시간 N초 (예: 5~8초) 동안 행동 불가
2) 동력 대량 소모 (예: 최대 동력의 20~30%) - 동력 시스템과 연결
3) 다운 중 포탑/기지는 무방비로 버텨야 함

C. 복귀
- 대기 종료 후 HP 일부(예: 50%)로 코어에서 부활.
- 같은 웨이브 내 다운 횟수 제한은 두지 않는다.
  (동력 소모가 반복 다운의 자연 제한 역할. 동력 부족 시 다운 → 동력 0 → 비상 상태로 연쇄)

D. 게임오버 조건 정리
- 게임오버는 기지 HP 0 단 하나로 유지한다.
- 플레이어 다운은 게임오버가 아니라 "동력과 방어선을 깎는 큰 실수"다.

E. 설계 의도
- 죽음을 즉시 패배가 아닌 자원 손실 이벤트로 만들어
  동력 0 비상 상태(9-4)와 같은 철학(실패 = 강한 생존 이벤트)을 유지한다.

8. 플레이어 동력 공격
======================================================================

8-1 ~ 8-5
[확정] (v1.0 동일)
- 마우스 방향 투사체 + 범위 폭발.
- 동력 공격 처치 시에만 소량 동력 환급. 환급량 < 소비량.

8-6. 콤보 환급 시각화
[신규 / 제안]
- 동력 공격 1회로 다수 처치 시 처치 수와 환급량을 즉시 팝업으로 표시한다.
  [예시] "x6 KILL  동력 +12"
- 다수 처치일수록 팝업 연출 강도를 1단계 높인다. (과한 이펙트 금지, UI 문서 10-2 준수)
- 목적: "잘 쏘면 돌려받는다"는 환급 설계를 체감시켜 동력 공격의 손맛을 만든다.

9. 동력 시스템
======================================================================

9-1. 동력의 역할
[확정] (v1.0 동일)
- 동력 공격 / 기지 이동 / 비상 웨이브 / 보스 대응 / 위험 관리를 잇는 핵심 자원.
- [신규] 플레이어 다운 복구 비용(7-5)도 동력과 연결된다.

9-2. 동력 감소
[개정] 감소 주체를 명확화한다.
- 시간 경과에 따라 감소한다.
- 기지가 피격되면 추가로 감소한다. (기지 피해 = 동력 계통 손상)
- 플레이어 동력 공격 사용 시 감소한다.
- 플레이어 다운 시 대량 감소한다. (7-5)
- [개정] 플레이어 개인 피격은 동력을 감소시키지 않는다. 플레이어 피격은 플레이어 HP만 감소.
  (플레이어 피격까지 동력을 깎으면 이중 페널티 + 자원 흐름 추적이 어려워짐)

[수치 미정]
- 초당 감소량 / 기지 피격당 감소량 / 동력 공격 1회 비용 / 다운 시 감소량

9-3. 동력 회복
[확정 + 개정]
- 동력 공격으로 적 처치 시 소량 회복.
- 0% 소진 시 비상 재충전으로 60%까지 회복.
- [개정] 정비 라운드 회복 3택에서 "동력 회복" 선택 가능 (5-2).
- [신규 / 제안] 자연 감소만으로는 웨이브 1개 동안 0%에 도달하지 않도록 설계한다.
  동력 0은 "동력 공격 남용 + 기지 피격 누적 + 다운"이 겹칠 때만 발생해야 한다.
  ("아껴도 어차피 0"이면 보존 선택이 무의미해지기 때문)

9-4 ~ 9-7. 동력 0% / 비상 재충전 / 60% 복귀 / 상태 흐름
[확정] (v1.0 동일)
- 0% → 기지 정지 + 동력 공격 봉인 + 비상 웨이브 + 자동 재충전
- 60% 도달 → 비상 웨이브 종료 + 재가동 애니메이션 + 이동 재개 + 복귀

9-8. 설계 목적
[확정] (v1.0 동일)

9-9. 비상 상태 극복 보상
[신규 / 제안]
- 비상 웨이브를 기지 HP 손실 없이(또는 일정 기준 이하 손실로) 버텨내면 보상을 준다.
  후보: 보너스 골드 / 희귀 증강 선택권 1회 / 경험치 보너스
- 목적: 비상 상태를 순수 페널티가 아닌 하이리스크 이벤트로 만든다.

10-5. 기지 전진의 게임플레이 의미
[신규 / 제안]
v1.0에서 전진은 "시각적 기준"에 그쳐, 비상 상태의 기지 정지가 체감 페널티가 없었다.
전진에 다음 의미를 부여한다.

A. 전진 = 보급
- 전진 경로에 보급 포인트가 배치된다. (웨이브 이벤트 슬롯 4-7과 연동)
- 기지가 전진 중일 때만 보급 포인트에 도달해 골드/경험치/소량 동력을 획득한다.
- 비상 정지 중에는 보급 포인트를 지나치지 못하고 놓친다. → 정지가 실질 손해가 된다.

B. 전진 속도와 동력 (선택 검토안)
- 동력 잔량 구간에 따라 전진 속도가 소폭 달라진다. (고동력 = 빠른 전진 = 보급 도달 증가)
- 단, 속도 차이가 웨이브 길이에 영향을 주면 타임라인 설계가 복잡해지므로
  보급 도달량에만 영향을 주는 방식으로 제한하는 것을 권장한다.

12-5. 적의 플레이어 공격 규칙
[신규 / 제안]
v1.0에 적→플레이어 공격 규칙이 없어 신설한다.

A. 기본 원칙
- 적의 1차 목표는 항상 포탑/기지다. (타워디펜스 압박 구조 유지)
- 플레이어는 "끼어들면 맞는" 존재로 정의한다.

B. 역할별 규칙
- 일반/탱커/원거리: 플레이어를 우선 타겟하지 않는다.
  단, 플레이어가 자신의 공격 범위 안에 있으면 공격 대상에 포함될 수 있다.
- 돌격형: 일정 거리 내 플레이어를 감지하면 플레이어로 타겟을 전환한다.
  (플레이어를 견제하는 유일한 상시 위협 역할)
- 엘리트/보스: 개별 패턴에 플레이어 대상 공격을 가질 수 있다.

C. 설계 의도
- 플레이어가 최전선에 나가 직접 처치하는 플레이에 리스크를 부여한다.
- 돌격형의 존재로 "안전한 원거리 딜링만 반복"하는 단조로움을 방지한다.
- 포탑 뒤 안전지대와 최전선 사이의 위치 선택이 지속적인 판단이 된다.

A. 포탑 변형 해금
- 15종 변형 중 시작 시 8종만 해금 상태.
- 나머지 7종은 런 클리어, 도전 과제, 누적 플레이로 해금.
- 해금 순서는 조작 이해도가 필요한 변형(레일, 파쇄 표식 등)을 후반에 배치.

B. 증강 풀 확장
- 일부 공통 증강과 변형 전용 증강도 해금 대상에 포함.

C. 난이도 승천 (Ascension)
- 클리어 시 다음 승천 단계 해금. 단계별 수정자 1개씩 추가.
  [예시] 적 체력 증가 → 동력 자연 감소 증가 → 정비 회복량 감소 → ...
- 목표 단계 수: 5~10 (콘텐츠 분량에 따라 결정)

D. 도감
- 적 / 보스 / 포탑 변형 / 증강 / Web 유니크 노드 도감.
- 수집 진행도가 곧 플레이 가이드 역할을 한다.

E. 시작 로드아웃 (선택 검토안)
- 시작 조건이 다른 로드아웃 2~4종.
  [예시] 표준형 / 동력 특화(최대 동력 증가, 플레이어 공격력 감소) /
  포탑 특화(시작 골드 증가, 플레이어 체력 감소)
- 캐릭터 로스터의 경량 버전. 재플레이 다양성의 핵심 장치.

F. 명시적 비원칙
- 영구 스탯 상승형 메타(공격력 +1% 누적 구매 등)는 사용하지 않는다.
  (해금 = 가로 확장. 세로 파워 인플레이션 금지. 실력 성장 체감 보존)

Rushitadel은 이동하는 요새 내부에서 플레이어가 직접 싸우고 6개의 자동 포탑을 관리하며,
